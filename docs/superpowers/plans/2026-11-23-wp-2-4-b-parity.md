# Paket B — Laporan Paritas Konsumen

## Tujuan

Bandingkan cermin sheet Database/Konsumen Progress dengan data `consumer_*` OASIS per cabang, tanpa mengubah sumber data. Gunakan service pembacaan dan pemetaan kanonis yang sudah ada. Simpan hasil terakhir untuk dipakai Paket C.

## Batasan

- Tidak mengubah data sheet atau `consumer_*`.
- Tidak mengirim NIK, nomor HP, alamat, atau field sensitif ke ekspor.
- Tidak membuat pemetaan status kedua. Reuse `ConsumerApplication::canonicalTransactionStatusDetails()` dan `KonsumenPipelineService::canonicalStage()`/mapping yang sudah dipakai pembacaan.
- Tidak merge ke `main`.
- Laporan dan UI Bahasa Indonesia.

## Langkah

1. **Inventaris kontrak existing**
   - Verifikasi `ConsumerReadComparisonService`, `LegacyConsumerReadService`, `LocalConsumerReadService`, DTO, controller, route, exporter, dan tabel migration.
   - Tambah model sumber sheet/OASIS hanya bila service existing tidak memenuhi kunci ID Transaksi, ID Konsumen Awal, ID PSJB.

2. **Kontrak parity terpusat**
   - Tambah DTO/result parity yang memuat branch, waktu pemeriksaan, metrik kanonis, dan baris selisih.
   - Resolver kunci mencocokkan berurutan berdasarkan ID Transaksi, ID Konsumen Awal, ID PSJB; tandai ambigu, hanya sheet, hanya OASIS.
   - Metrik: jumlah transaksi per status `LANJUT`/`MUNDUR`, akad per bulan, proses terakhir, kavling terisi.
   - Status legacy memakai mapping kanonis existing; legacy tidak dikenal ditandai perlu review.
   - Field pribadi tetap tidak masuk payload ekspor.

3. **Snapshot hasil**
   - Tambah migration idempoten untuk tabel snapshot dan detail baris bila belum ada struktur cocok.
   - Simpan tanggal, branch, status lulus/gagal, ringkasan JSON, metrik JSON, dan selisih JSON/relasi detail.
   - Tambah changelog idempoten sesuai aturan repo.

4. **Command read-only**
   - Tambah `consumer:parity-report {branch} {--xlsx}`.
   - Branch menerima route key yang sudah dipakai aplikasi; validasi branch aktif/scope command.
   - Tampilkan ringkasan dan selisih Bahasa Indonesia.
   - `--xlsx` memakai PhpSpreadsheet yang sudah tersedia; ekspor hanya field operasional non-PII.
   - Simpan snapshot terakhir setelah report berhasil.

5. **Halaman superadmin**
   - Tambah halaman ringkasan per cabang dan detail selisih.
   - Gunakan route/controller/policy existing, tanpa otorisasi menu saja.
   - Tampilkan snapshot terakhir, status lulus/gagal, metrik, dan daftar selisih.

6. **Tes**
   - Service: cocok penuh, hilang sheet, hilang OASIS, beda status, beda tanggal akad, beda kavling, status legacy.
   - Matching: masing-masing ID, konflik/duplikat, fallback dan ambiguity.
   - Snapshot: tanggal, status, ringkasan, cabang.
   - Command: read-only, output Bahasa Indonesia, `--xlsx`, tidak ada PII.
   - HTTP: superadmin boleh, non-superadmin ditolak, akses branch invalid ditolak.

7. **Verifikasi dan delivery**
   - `php artisan test` terfokus lalu suite penuh.
   - Pint, `git diff --check`, `view:cache`, build bila markup/JS berubah.
   - `graphify update .` bila tersedia.
   - Commit terpisah, push ke `prd-v3/wp-2.4-b-parity`; tidak merge main.
