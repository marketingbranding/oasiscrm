# Phase 2.6 Organization Relationship Semantics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Represent formal reporting and Sales Coordinator membership as separate typed canonical relationships while preserving legacy production reads, compatibility projections, and the blocked cutover gate.

**Architecture:** Reuse `organization_assignments.relationship_type` with `reports_to` and a new `sales_team_member_of` value. `OrganizationGraphService` owns typed graph validation/writes; `SalesCoordinatorAssignmentService` remains the compatibility writer for `sales_coordinator_sales` and dual-writes the typed Sales-team edge. Reporting traversal and Sales-team traversal use separate scopes and never union authority implicitly.

**Tech Stack:** PHP 8.3, Laravel 13, Eloquent, SQLite/MySQL migrations, PHPUnit, Artisan diagnostics, Vite.

**Spec:** `docs/superpowers/specs/2026-10-30-phase-2.6-organization-relationship-semantics-design.md`

## Global Constraints

- Keep `config('organization.graph_mode')` and production reads on `legacy`.
- Do not remove `users.supervisor_user_id`, `sales_coordinator_sales`, compatibility writers, or legacy projections.
- Do not execute global/production backfill, graph cutover, Phase 3, route changes, navigation changes, permission redesign, or broad UI work.
- Compare like relationships only: legacy supervisor ↔ `reports_to`; legacy Coordinator mapping ↔ `sales_team_member_of`.
- Relationship edges do not grant permissions; module authorization still requires explicit permission, workspace scope, organization scope, and target policy checks.
- Preserve effective dates, historical rows, auditability, optimistic conflict checks, branch/project boundaries, and non-destructive dry-run behavior.
- Use existing Laravel/PHPUnit/PhpSpreadsheet dependencies; add no dependency.
- Every behavior-changing release entry must use an idempotent migration and Indonesian user-facing copy.

## Review Focus

- A Sales user has both an active Supervisor and an active Coordinator: both typed edges must coexist without a false conflict or reporting/team traversal contamination. Test in Tasks 1, 2, and 4.
- A formal reporting edge points to a Coordinator: it must not create or replace Sales-team membership. Test in Task 1.
- A Sales-team edge is changed or ended: only Sales-team reads and legacy mapping history change; reporting ancestry remains unchanged. Test in Task 2.
- Historical-only relationships must remain visible to historical diagnostics without granting current access. Test in Tasks 2 and 3.
- Invalid, duplicate, cross-branch, inactive, or ambiguous same-type relationships must remain blocked and auditable rather than guessed. Test in Tasks 1 and 3.

## File Map

- Modify `app/Models/OrganizationAssignment.php`: add typed relationship constants/scopes while keeping `current()` reporting-compatible.
- Modify `app/Services/OrganizationGraphService.php`: add Sales-team edge validation/traversal/writes and remove the current reporting-to-Coordinator projection coupling.
- Modify `app/Services/SalesCoordinatorAssignmentService.php`: keep legacy mapping writes and synchronize the typed Sales-team edge.
- Modify `app/Services/SalesTeamScopeService.php`: use typed Sales-team edges in canonical mode; keep legacy mode on `sales_coordinator_sales`.
- Modify `app/Services/OrganizationBackfillService.php`: backfill reporting and Sales-team dimensions independently with deterministic conflict evidence.
- Modify `app/Services/OrganizationParityService.php`: compare typed dimensions independently and classify remaining missing/conflicting edges correctly.
- Modify `app/Services/OrganizationGraphRemediationService.php`: allow only approved, expected-state typed repairs without collapsing dimensions.
- Add `database/migrations/2026_10_30_000004_add_phase_2_6_organization_relationship_semantics_changelog.php`: idempotent Changelog entry.
- Modify/add focused tests under `tests/Feature/`: graph, Sales-team scope, parity, backfill, remediation, module shadow access, and Changelog/documentation contracts.
- Add `docs/ORGANIZATION_RELATIONSHIP_SEMANTICS_PHASE_2_6.md`: final evidence report with required A–R sections and exact diagnostics.
