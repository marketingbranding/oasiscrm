# WP-2.1 Alih Lead Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement BR-54, BR-55, and D27: atomic lead transfer inside active coordinator teams, immutable history, owner notification, and an unowned-lead queue after Sales deactivation.

**Architecture:** Add `sales_lead_transfers` and an application service as the only mutation boundary. Coordinator actions resolve active team membership at action time; queue ownership uses the Sales person's last active coordinator team, with Superadmin fallback. Deactivation remains immediate and moves active non-terminal leads to an auditable queue state.

**Tech Stack:** Laravel 13, PHP 8.3, Eloquent, Blade/Alpine, PHPUnit, existing notifications/activity-log/scope services.

**Spec:** `docs/product/PRD_OASIS_CRM_V3.md` BR-54/BR-55, D27; decisions recorded in `docs/product/PRD_V3_IMPLEMENTATION_LOG.md`.

## Global Constraints

- Only active Sales-team assignments count for coordinator authorization at transfer time.
- Transfer is atomic; failure identifies the lead causing failure.
- Deactivation is immediate; former Sales loses access immediately.
- Active non-UTJ/Gugur leads enter the unowned queue.
- Only Coordinator handles queue normally; Superadmin handles it when no active coordinator exists.
- Notifications are in-app plus activity log; notification type is `lead_transferred_to_me`.
- Branch Manager/Admin Cabang remain read-only for historical-owned leads.
- No merge to `main`; each WP branch is pushed for review before phase merge.

## Review Focus

- Transfer target belongs to the same active coordinator team, not merely same branch.
- Mixed batches fail atomically and name the first invalid lead.
- Deactivated Sales cannot authenticate or access old lead routes, while queue records remain actionable.
- UTJ/Gugur leads never enter unowned queue.
- Sales with no active coordinator uses last active team; no-coordinator queue is Superadmin-only.
