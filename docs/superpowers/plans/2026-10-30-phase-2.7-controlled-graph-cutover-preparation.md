# Phase 2.7 Controlled Graph Cutover Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove controlled canonical graph population, parity, shadow reads, scoped graph reads, rollback, and cutover health without changing production from legacy mode or performing global writes.

**Architecture:** Add a centralized `OrganizationGraphModeService` that normalizes mode and activation context, then integrate it at the existing reporting, Sales-team, and organization-scope read seams. Extend backfill with isolated-write guards and explicit selection, add a deterministic health-gate service/command, and preserve legacy readers/writers for shadow comparison and rollback.

**Tech Stack:** PHP 8.3, Laravel 13, Eloquent, PHPUnit, Artisan, SQLite/MySQL configuration, existing organization services.

**Spec:** `docs/superpowers/specs/2026-10-30-phase-2.7-controlled-graph-cutover-preparation-design.md`

## Global Constraints

- Production remains `graph_mode=legacy`; no production cutover or global backfill.
- Phase 2.7 activation is environment/config-only; no UI/database activation flag.
- Empty allowlists fail closed to legacy; user/branch matching is OR; branch matches apply only to the branch context being evaluated.
- Outside tests, graph mode requires an explicit user/branch allowlist match.
- Controlled writes require local/testing environment, explicit write confirmation, non-production database identity, and explicit non-global selection.
- Preserve `users.supervisor_user_id`, `sales_coordinator_sales`, typed assignments, historical rows, compatibility writers, permissions, routes, navigation, and existing transaction conventions.
- Graph relationships never grant capability; permission, workspace, organization scope, and target policy checks remain authoritative.
- Invalid configuration, graph integrity failure, ambiguous typed edges, and unsafe activation fall back to legacy.
- The existing `canonical` configuration value remains a backward-compatible alias for internal `graph` semantics; raw configured metadata remains observable for diagnostics.
- Do not add dependencies, Redis/Reverb, a generic feature-flag platform, or Phase 3 behavior.
- Every behavior-changing release entry requires an idempotent Indonesian Changelog migration.

## Review Focus

- A missing/invalid mode, malformed allowlist, production environment, or empty graph allowlist must never activate graph reads; cover in Task 1.
- A branch allowlist must activate only the evaluated branch context and never widen cross-branch scope; cover in Tasks 1 and 6.
- A controlled write must reject missing guards before mutation and roll back both representations on later failure; cover in Tasks 2 and 7.
- Ambiguous, stale, cross-branch, cross-project, inactive, and invalid-role typed edges must remain excluded and reported; cover in Tasks 3, 4, and 6.
- Shadow/graph reads must preserve relationship separation and capability boundaries across direct URLs, exports, JSON, bulk, and sync paths; cover in Tasks 5 and 6.
