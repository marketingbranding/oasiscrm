# Phase 2.5 Organization Parity Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Classify every known organization parity mismatch, safely repair only high-confidence canonical relationships in isolated/audited paths, and keep the cutover gate blocked while critical or ambiguous differences remain.

**Architecture:** Extend the existing parity service and command with severity, access direction, confidence, evidence, recommendations, conflict filters, and a diagnostic cutover gate. Enrich the dry-run backfill report, add a narrow approved-repair service that is independently idempotent-testable but has no global apply command, and preserve legacy production reads and compatibility writers.

**Tech Stack:** PHP 8.3, Laravel 13, Eloquent, Artisan, PHPUnit, SQLite test database.

**Spec:** `docs/superpowers/specs/2026-10-30-phase-2.5-organization-parity-remediation-design.md`

## Global Constraints

- Do not switch `OrganizationScopeService` default reads or make `organization_assignments` production-authoritative.
- Do not execute production/global database write backfill.
- Do not remove `supervisor_user_id`, `sales_coordinator_sales`, compatibility writers, legacy services, routes, permissions, or historical data.
- Do not automatically choose Sales Coordinator over legacy supervisor for ambiguous dual-parent conflicts.
- Do not add restrictive database constraints before existing data is proven compatible.
- Keep parity diagnostics machine-readable and non-mutating.
- Preserve all existing Phase 1/Phase 2 worktree changes and unrelated untracked files.

## Review Focus

- **Access expansion:** graph allow / legacy deny must be classified as security-critical and block the gate; test both branch/project and user/team records.
- **Ambiguous dual parents:** active Coordinator and legacy supervisor conflicts must remain unresolved with evidence and confidence, never be silently assigned by precedence.
- **Approved repair safety:** an exact high-confidence repair must revalidate current state, role/workspace/cycle rules, write idempotently, and preserve audit/projection behavior.
- **Historical contamination:** ended mappings and branch memberships must not become current team access or be repaired as active relationships.
- **Gate completeness:** unknowns, access loss, unresolved conflicts, stale/unclassified anomalies, non-idempotent backfill, and cycle failures must block readiness.
